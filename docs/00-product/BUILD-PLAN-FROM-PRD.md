## Constraints (from AGENTS.md / ADRs)
- Evidence-first AI; never fabricate telemetry; adapter boundaries; AdminLTE 4 React; server-managed sessions; no local password login unless ADR 0010 controls implemented (they are).
- No remote write actions until approval/action framework slice.
- Secure by default, least privilege, fail closed.
- Contracts under `contracts/**` are authoritative; changes require matching OpenAPI/JSON-schema updates.

## Current state (through build order steps 1–3)
- Foundation, CI, security gates, contracts base, canonical API path `/api/v1`.
- S1 slice implemented: OIDC login + local credentials with MFA (ADR 0010), sessions, RBAC, AdminLTE shell, overview aggregate, LibreNMS devices/interfaces/alerts, device table/detail, interface table, source-health states, E2E harness + security matrix tests.

- Topology (S3 steps 1–4): canonical `topology.schema.json`, `/api/v1/topology` endpoint, NetBox active cables as the only edge source (states `not-connected` / `unknown` / `ok`; only terminations that resolve to devices on both ends become edges), `/network/map` UI with explicit states + interactive layered canvas (pan/zoom/fit), contract + parser tests (no-source/empty/valid graph). Reconciliation findings consumed in edge context: nodes carry `reconciled` + `finding` (`missing-discovered` / `status-mismatch` only, finding requires `reconciled=true` in schema/pydantic/parser); `unknown-discovered` stays in `/reconcile/findings`. ### E12 - Forecasting/Optimisation (PRD 21, 35; IMPLEMENTATION-ROADMAP E12; `docs/12-implementation/REPORTING.md` capacity)
Stories: capacity forecast, predictive warning against an operator limit, safe (advisory) recommendations, the capacity report.

1. DONE **Step 13 - capacity forecasting from source-reported history, advisory recommendations, capacity report (CSV)** (2026-10-18, committed on `main`; contract-first, strict TDD). Delivered:
   - **Method (no model).** Daily organisation-wide byte totals from the ClickHouse flow store. A straight-line trend (OLS) or a weekly seasonal-naive repeat, chosen by lower mean absolute error on the history (the line is judged in-sample, which favours it); a stated horizon (1-30 days); an approximate 95 % band (Student-t for the degrees of freedom, so a 14-day history is not given a normal-sized band); values floored at zero and rounded half up. Minimum history: 14 observed days, at most 25 % gaps, newest day at most 3 days old, horizon at most half the observed days; otherwise `insufficient-data` with the reason, the measured days it had and no projected point. A forecast starts the day after the newest observed day.
   - **Honesty.** A day with no data is absent, never zero; a first day the store covers only from mid-day is dropped as partial; no flow source is `not-connected`, an unreadable one is `unknown` (error text never returned). `wan-utilisation` and `inventory-growth` are listed as `not-connected` (reason `no-history-source`): LibreNMS gives current rates only, NetBox current state, and Netsight stores probe samples (reachability/latency), not utilisation. Every projected value sits in `forecast` with a band; the response is labelled `is_forecast` with a fixed notice; pydantic, the TS parser and (where expressible) JSON Schema refuse a forecast on a series that is not `ok`.
